# 平台与改编硬约束清单（写作前必读）

> **这些坑的共同特点：写完才发现，返工成本极高。**
> 本文件把所有"事后才知道"的约束前置到开工前。

---

## 一、平台硬约束（必须前置）

```yaml
番茄:
  - 未签约作品无搜索（无自然流量，无法试水）
  - 签约即独家（不能同时发其他平台）
  - 章名最少 5 字（2-4 字提交失败）
  - 日更 6000-9000 字（稳定推荐的关键）
  - 前 3 章决定生死（读者耐心极低）

七猫:
  - 同属免费平台，逻辑与番茄类似
  - 优势品类: 战神、赘婿、玄幻、历史
  - 具体政策以编辑答复为准（勿凭经验）

起点:
  - 付费订阅，读者耐心较高
  - 可慢热，重设定
  - 章名可文艺（格调 > 钩子）

通用:
  - 签约前: 一稿多投不违规（可同时谈）
  - 签约后: 独家，违约会被降权/扣全勤/解约
  - 两边都拿全勤 = 不可能
```

### 投稿谈判要点（你已有的筹码）

```yaml
带去谈的材料（远超普通投稿者）:
  □ 400 章完整章纲（证明不断更）
  □ 人设库 + 金手指规则（证明设定自洽）
  □ 伏笔总表（证明长线可控）
  □ 前三章正文（证明文笔）
  □ 日更计划（证明产能）
  □ 评审机制说明（证明质量可控）

必问编辑的三个问题:
  1. 这个题材你们站近期数据如何？
  2. 同类型天花板在哪？
  3. 我的前三章钩子够不够？

谈判定位:
  "我不是有个想法，我是有完整工业方案"
  → 从"求签约"变成"给平台稳定产能"
```

## 二、审核红线（一票否决）

### 通用红线

```yaml
□ 涉政: 现实政治人物/事件/制度影射
□ 涉黄: 露骨描写、擦边情节
□ 暴力: 详细虐杀、猎奇、屠城细节
□ 违法: 详细犯罪手法教学
□ 自杀/自残: 详细描写
□ 宗教/民族: 敏感表述
□ 未成年人: 不当描写
```

### 类型专项红线

```yaml
职场/都市（默者类）:
  □ 技术描写不可复现（改数据库必须停留在流程层面）
     ✗ 具体命令/SQL 语句
     ✓ "一条数据库更新语句"
  □ 无真实企业名/品牌名/机构名
  □ 不宣扬"职场无意义""努力无用"（情绪底色必须有希望）
  □ 疾病描写一笔带过（不渲染、不卖惨）

历史/架空（狂臣类）:
  □ 无真实朝代名/历史人物/可对应事件
  □ 暴力写意化（"刀落"两字，不写过程）
  □ "异族/匈奴"完全架空，不影射现实民族与边疆
  □ 朝堂权谋全架空，无现实体制对应

玄幻/修仙:
  □ 力量体系不与现实宗教挂钩
  □ 无现实地名/民族影射
```

### 情绪红线（容易被忽略）

```yaml
问题: 通篇压抑、宣扬绝望、虚无主义

判定标准:
  ✗ "努力无用，底层永无出头之日"
  ✓ 有压力、有反击、结局给希望

处理:
  - 主角可以惨，但不能"认命"
  - 结局必须给"规则可被修复"的希望
  - 配角要有"微光"（温暖细节）
```

## 三、听书（TTS）硬约束

```yaml
为什么重要:
  免费平台的 AI 听书是重要流量入口
  格式乱 = 听书版报废 = 少一个免费入口

三轨分离:
  旁白 / 对白("") / 独白(『』单独成段)

一人一段（音色分配）:
  ✗ 两人挤一段 → TTS 一个音色读完 → 炸点全毁

称谓语统一:
  ✗ 同章内"萧彻/镇北王/王爷/他"乱跳 → 音色乱跳
  ✓ 同章统一称谓，身份切换只在章与章之间

数字可读化:
  005→零零五 / 2/5→五分之二 / 186→一百八十六 / N+1→N加一

禁止:
  引号嵌套 / 括号大段 / 引号不闭合 / 破折号连用(>3) /
  无标点长段 / 颜文字 / 感叹号连用
```

## 四、影视化硬约束（前置到写作）

```yaml
核心: Show Don't Tell —— 不是修辞，是改编刚需

动画路径（大场面）:
  □ 每个炸点"能画成一帧"
  □ 大场面四要素: 空间 / 规模 / 光影 / 声音
  □ 镜头三段式: 远景 → 中景 → 特写
  □ 动作四拍: 起 → 承 → 转 → 合(定格)
  □ 角色有视觉符号（剪影可辨）
  □ 每章 = 1 集，章末留炸点

真人剧路径（内心戏）:
  □ 内心外化（物件/微表情/动作/环境/留白）
  □ 独白 ≤3 处/章（多了变广播剧）
  □ 每场给"空间+时间+人物"
  □ 声音设计（高光时刻用"静音"）

通用禁止:
  ✗ 抽象情绪（不可画/不可演）
  ✗ 关键转折只发生在"脑海里"
  ✗ 场景模糊（美术/导演无从下手）
  ✗ 连续多章同场景（视觉疲劳）
```

## 五、"写完才发现"清单（开工前逐条确认）

```yaml
□ 章名是否满足平台最少字数？（≥5）
□ 是否签约前就把市场调研做完了？（番茄无试水机会）
□ 技术/历史描写是否已泛化？（避免审核卡 + 听书灾难）
□ 情绪底色是否有希望？（避免虚无判定）
□ 每章是否一人一段？（听书音色）
□ 数字是否可读化？（TTS 断句）
□ 每章是否 = 1 集？（改编切割）
□ 存稿是否 ≥30 章？（防断更）
□ 角色称谓是否统一？（音色绑定）
□ 有无"不可拍"的抽象描写？（改编前置）
```
