# 锁定层 · 否定式定义法（本方法论最重要的发现）

> **核心发现：用"不能做什么"定义角色，比"要做什么"精确 10 倍。**
> **极致形态：用"对立面"定义调性（默者 = 不是狂臣）。**

---

## 一、为什么否定式优于肯定式

```yaml
实验对照:
  肯定式 prompt: "王默是个克制的人"
    → LLM 输出: 沉默寡言（但偶尔还是会热血发言）
    → 问题: "克制"是模糊的，模型用自己的理解填充

  否定式 prompt: "王默不能: 怒吼/解释/炫耀/主动挑衅/事后得意"
    → LLM 输出: 稳定克制
    → 原因: 禁止项是离散的、可检查的

原理:
  肯定式给的是【方向】（模糊，模型自行插值）
  否定式给的是【边界】（明确，模型知道红线在哪）
  → LLM 擅长遵守边界，不擅长猜方向
```

## 二、人设卡的三段式结构

```yaml
第一段 · 基础属性（数据，用于一致性校验）:
  姓名/年龄/身份/外貌/家庭/财务状况
  → 作用: 硬数据校验表（错一处即打回）

第二段 · 性格肯定项（少量，给方向）:
  "沉默、理智、记仇、护短"
  → 控制在 3-5 个词，多了会稀释

第三段 · 性格禁止项（重点，给边界）:
  ✗ 不怒吼
  ✗ 不解释自己的行为
  ✗ 不炫耀战果
  ✗ 不主动挑衅（只反击）
  ✗ 不用金手指毫无顾虑
  ✗ 不变成嘴炮王
  → 作用: 漂移预警信号（命中即打回）
```

### 漂移预警信号表（可直接复制）

```yaml
主角漂移信号（命中任一 → 该章打回重写）:
  □ 开始"解释"自己的计划（应为沉默执行）
  □ 开始"怒吼/情绪失控"（应为克制/冷）
  □ 事后"炫耀/得意"（应为无所谓）
  □ 主动挑衅（应为只反击）
  □ 使用能力毫无顾虑（应有边界意识）
  □ 变成"嘴炮王"（应为行动派）
  □ 突然懂了不该懂的领域（应保持专业边界）
```

## 三、调性的"对立面定义法"（本方法论独创）

```yaml
问题: 单本书定义"冷感"，模型不知道边界在哪

解法: 建立对立项目，互相定义
  默者（冷感）←→ 狂臣（炸裂）

  默者的定义 = "不是狂臣":
    - 狂臣当场掀桌   → 默者按流程走
    - 狂臣嚣张明牌   → 默者沉默无声
    - 狂臣要"满场寂静" → 默者要"无人察觉"
    - 狂臣章末炸点   → 默者章末留白

  狂臣的定义 = "不是默者":
    - 默者隐忍等待   → 狂臣当场爆发
    - 默者走OA流程   → 狂臣直接拔刀
    - 默者章末留白   → 狂臣章末炸点
    - 默者压抑       → 狂臣嚣张
```

### 对立定义对照表（模板，开新书时填）

| 维度 | 项目A（默者·冷感） | 项目B（狂臣·炸裂） |
|---|---|---|
| 爽点类型 | 延迟满足 | 即时满足 |
| 反击方式 | 改数据库/发邮件 | 拔刀/掀桌 |
| 反派感知 | 无感知（事后才发现） | 当场崩溃 |
| 章末钩子 | 留白/物件 | 炸点/金句 |
| 情绪 | 压抑→微光 | 压抑→爆发 |
| 禁用词 | 感叹号、嚣张词 | 隐忍词、流程词 |
| 章名公式 | 数据/系统语言/无声反差 | 挑衅/动作/数字反差 |

```yaml
关键价值:
  - 新项目可复用这张表（换内容，不换结构）
  - 评审时"防对方味"是最高效的检测项
  - 两个项目交替创作，反而互相冲淡 AI 味
```

## 四、金手指的"边界优先"法则

```yaml
❌ 错误写法（能力清单）:
  "主角有最高权限，可以修改系统一切"
  → 无敌 → 无冲突 → 故事崩

✅ 正确写法（先写边界）:
  能力: 可修改系统数据
  边界:
    - 仅限本公司体系内
    - 必须"看起来合规"（不能凭空造钱）
    - 每次使用留痕（会被反查）
    - 不能主动暴露（暴露即失效）
    - 有使用代价（风险/暴露可能）
  → 有边界才有冲突
```

### 三条腿法则（推荐结构）

```yaml
给主角 3 个能力支柱，每根都有明确短板:

  例（狂臣）:
    腿1 · 密诏虎符: 有权，但【有时效/只调北境军】
    腿2 · 夜枭情报: 有眼，但【会失手/会被渗透】
    腿3 · 个人武力: 有刀，但【会受伤/不能分身】

  例（默者）:
    腿1 · 系统后门: 能改数据，但【必须合规/会留痕】
    腿2 · 八年经验: 懂系统，但【只是运维/无职权】
    腿3 · 留痕反查: 能取证，但【需要时间/不能即时】

优势:
  - 三条腿可组合出不同解法（避免单一套路）
  - 任意一条失效，仍有故事可讲
  - 天然防止"无敌"
```

## 五、锁定层交付物清单（开新书必建）

```yaml
□ 人设卡（每个主要角色）:
    - 基础属性（硬数据）
    - 性格肯定项（3-5 个）
    - 性格禁止项（5-8 个）← 重点
    - 漂移预警信号（可检查）
    - 视觉符号（1-2 个，影视化用）
    - 语言特征（口头禅/句式）

□ 调性定义卡:
    - 本项目是什么（肯定）
    - 本项目不是什么（对立面）← 重点
    - 与对立项目的对照表

□ 金手指规则卡:
    - 能力（简单）
    - 边界（详细）← 重点
    - 三条腿结构
    - 使用代价

□ 世界观规则卡:
    - 力量/职级体系
    - 势力分布
    - 不可违背的物理/社会规则
```

## 六、一句话总结

> **不要告诉 AI"要怎样"，要告诉 AI"不许怎样"。**
> 人设用禁止项锁死，调性用对立面定义，金手指先写边界再写能力。
> **锁定层的质量，决定了后面 400 章会不会跑偏。**
