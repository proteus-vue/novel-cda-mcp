# CDA 约束驱动创作法 · 总纲

> **Constraint-Driven Authoring（约束驱动创作法）**
> 形象名：**「笼中跳舞」**——先建笼子，再让 AI 跳舞。
> （编者注：本方法论落地为 MCP 工具时，另定神话形象名「大禹」——取大禹治水"堵不如疏、建笼立规"之意；「笼中跳舞」为方法论口号，二者并存不冲突。此处保留方法论原文。）
>
> **一句话核心：不教 AI 怎么写，只告诉 AI 不能怎么写。**

---

## 一、这套方法论解决什么问题

```yaml
传统 AI 写作的失败模式:
  给 AI 一个创意 → AI 自由发挥 → 前 3 章惊艳 →
  第 30 章人设崩 → 第 100 章伏笔断 → 第 200 章注水 → 烂尾

根因（不是 AI 不行）:
  - LLM 不缺创造力，缺"边界"
  - 单靠 prompt 无法约束百万字
  - 人脑记不住 400 章的伏笔与数据
  - "感觉对了"无法传承给下一次生产

CDA 的解法:
  把"创作"从【灵感驱动】改造成【约束驱动】
  → 先把自由度锁死，再让 AI 在笼子里发挥
  → 把"记忆"外包给表格与编号
  → 把"判断"外包给评审机制
```

## 二、五层架构（从定位到发布）

```
定位层  →  锁定层  →  结构层  →  执行层  →  质检层
(生死)     (不跑偏)    (不崩)     (能落地)    (能发布)
```

| 层 | 核心问题 | 交付物 | 失败后果 |
|---|---|---|---|
| **定位层** | 卖给谁？在哪卖？改成什么？ | 定位决策卡 | 方向错，全盘皆输 |
| **锁定层** | 什么绝对不能写？ | 人设禁止项 + 金手指边界 + 调性对立定义 | 人设崩、金手指无敌 |
| **结构层** | 百万字怎么不断线？ | **卷群架构**（可生长）+ 逐章章纲 + 两级伏笔表 | 伏笔断、后期注水 |
| **执行层** | LLM 怎么落地？ | Prompt + 模板 + 格式 + 字数规则 | AI 味、油腻味、不可拍 |
| **质检层** | 能不能发？ | 过程评审 + 发布闸门 + 回调方案 | 违规被封、读者流失 |

## 三、十大原则（方法论的灵魂）

### 原则1 · 约束优先于创意
```yaml
❌ 传统: "写一个职场逆袭故事，要爽" → AI 自由发挥
✅ CDA: 先定 20 条"禁止项"，再让它写
理由: LLM 的能力远超你的想象，缺的只是边界
```

### 原则2 · 否定式定义 > 肯定式定义（最重要）
```yaml
❌ 肯定式: "王默要克制" → AI 不知道什么叫克制
✅ 否定式: "王默不能: 怒吼/解释/炫耀/主动挑衅"
✅ 极致: "默者 = 不是狂臣"（用对立面定义）

发现过程:
  做两个宇宙时意外发现——用【对立面】定义调性，
  比用【同义词】精确 10 倍。
  因为"克制"是模糊的，"不是狂臣"是明确的。
```

### 原则3 · 边界 > 能力
```yaml
❌ 弱写法: 主角有超能力 → 无敌 → 无冲突 → 崩
✅ CDA: 先写"能力边界"，再写"能力"

实证（狂臣三条腿）:
  密诏: 有时效（不是永久王牌）
  虎符: 只调北境军（调不动京营）
  夜枭: 会失手、会被渗透
→ 有边界才有冲突，有冲突才有故事
```

### 原则4 · 架构可生长（终点开放）
```yaml
❌ 旧: 预设"四卷 400 章完结"
   问题: 400 章是我为"可控"设的工程框，不是创作规律
✅ 新: 骨架固定（卷群），终点开放
   每个卷群自带完整起承转合 → 可续可收
   冲突套娃 + 体系刷新 → 长度自然生长
   留"生长点" → 根据数据反馈决定展开或收尾

洞察:
  大神不是"能写 2000 章"，是"每章都知道下一章往哪长"。
  长篇是长出来的，不是规划出来的。
```

### 原则5 · 编号系统是"外部大脑"
```yaml
问题: LLM 上下文有限，人脑也记不住 400 章
解法: 把记忆外包给表格
  F# / G# 编号 + 埋设章 + 回收章 → 伏笔不断
  人设卡 + 硬数据校验表 → 数据不乱
  → 表格是无限的，上下文是有限的
```

### 原则6 · 反 AI 味 = 反抽象（强制具体）
```yaml
洞察: AI 味的本质是【用抽象概念替代具体感知】

✗ "他内心五味杂陈"   → ✓ "他把凉透的枸杞水喝完"
✗ "全场震惊"         → ✓ "御史的笏板掉了"
✗ "气势如虹"         → ✓ "茶盏碎在裴衍脚边"

解法（可量化）:
  抽象词红黄牌表 + 强制"物件/动作/数字/个体反应"
```

### 原则7 · 反机械感 = 不匀称
```yaml
洞察: 机械感来自【均匀】，不是来自【规则多】

✗ 每章恰好 2500 字 → 机器排的
✗ 每章都带钩子     → 疲劳廉价
✗ 全用短名         → 平台不让且轻浮

✅ 解法: 分层 + 浮动 + 不匀称
  字数: 静场 1500 / 常规 3000 / 高潮 5000（浮动）
  章名: 前30章全钩子 / 名场面用短名 / 情感章克制
  → "不匀称"恰恰是人味的来源
```

### 原则8 · 评审分层（过程 ≠ 闸门）
```yaml
混淆的后果:
  只用过程评审 → 过松，发出事故（违规/崩人设）
  只用闸门评审 → 过严，无法量产

✅ CDA:
  过程评审（每章）: 管质量，AI味/油腻/漂移
  发布闸门（批次）: 管生死，合规/黄金三章/伏笔
  → 两层各司其职
```

### 原则9 · 改编前置（删掉不可拍的）
```yaml
洞察: Show Don't Tell 不是修辞技巧，是改编刚需

补拍期才发现"画不出来" = 写作期成本的 100 倍

✅ 写作期就删:
  抽象情绪（不可画）→ 外化为动作/物件
  内心转折（不可演）→ 外化为微表情/对白留白
```

### 原则10 · 平台硬约束前置
```yaml
血泪教训（都是"写完才发现提交不了"）:
  - 番茄: 不签约无搜索（无自然流量，没法试水）
  - 章名: 最少 5 字（2-4 字短名提交失败）
  - 签约: 默认独家（不能两边发）
  - 敏感: 技术细节/朝代影射/民族表述

✅ 解法: 建立【平台硬约束清单】，写作前必读
```

### 原则11 · 项目间隔离（防串味）
```yaml
洞察: LLM 会不自觉混用风格
  写惯了狂臣的"炸裂"，回头写默者会带出"嚣张"

✅ 解法: 每个项目建独立"语言环境"
  - 独立编号（F# vs G#）
  - 独立提示词
  - 独立词表（冷感词 vs 炸裂词）
  - 独立"防对方味"的评审项
  → 隔离是刚需，不是洁癖
```

## 四、本方法论的"可计算化"

> 创作看似不可量化，但 CDA 把它变成了可计算的工程：

| 维度 | 可量化指标 |
|---|---|
| 爽点密度 | 每章 ≥1 暗爽；每 3 章 ≥1 明爽；每卷 ≥3 名场面 |
| 字数分布 | 按类型浮动，禁止"每章都恰好 2500"（机械感检测） |
| 伏笔健康度 | 回收率 = 已回收/已埋设；凭空回收 = 0（一票否决） |
| 章名合规 | 可见字数 ≥5；总长 ≤15；感叹号 ≤3/卷 |
| AI 味评分 | 红牌词 ≤1/章；无总结升华；抽象→具体 |
| 调性漂移 | 漂移预警信号命中数 |
| 发布评分 | 五步百分制，≥80 放行 |

**结论：当创作变成"指标 + 规则 + 评审"，它就从手艺变成了工程——这正是批量生产的前提。**

## 五、方法论的适用边界（诚实说明）

```yaml
✅ CDA 擅长:
  - 商业类型小说（爽文、悬疑、言情、历史）
  - 长篇量产（50万-500万字）
  - 需要控制质量下限的系列化生产
  - 有明确平台与改编目标的作品

❌ CDA 不擅长:
  - 纯文学实验、意识流、极致个人风格
  - 短篇（约束成本高于收益）
  - 追求"不可预期的天才时刻"（约束会压制意外惊喜）

⚠️ 关键认知:
  CDA 保证的是【质量下限】，不是【艺术上限】。
  它让"80 分的作品稳定量产"，但无法保证"95 分的神作"。
  神作仍需人类作者的不可替代判断。
```

## 七、一句话总结

> **CDA 不是"让 AI 写小说"，是"给 AI 建一座创作工厂"。**
> 定位层定生死，锁定层防跑偏，结构层防崩盘，
> 执行层保落地，质检层保发布。
> **五层齐备，就能从"碰运气"变成"可复制"。**
