# 开新书 SOP · 批量生产检查清单

> **本文件回答一个问题：如何用 CDA 快速开第 3、4、5 本新书？**
> 7 步走完，一本新书的基础设施就建好了。

---

## 七步开新书 SOP

### 第 1 步 · 定位（1 天）

```yaml
动作: 填定位决策卡
输出: 平台 / 受众 / 改编形态 / 对标 / 差异化
检查:
  □ 平台规则已确认？（番茄无试水 / 独家 / 章名≥5字）
  □ 改编形态已定？（动画 or 真人剧）
  □ 差异化一句话说得清？
  □ 代入门槛评估过？
```

### 第 2 步 · 找对立面（0.5 天）★ 关键

```yaml
动作: 给新项目找一个"对立参照"
  已有项目: 默者（冷感）←→ 狂臣（炸裂）
  新项目: 找一个新的调性维度

方法:
  - 如果已有项目库: 新项目 = "不是已有任何一个"
  - 如果是第一个项目: 虚构一个对立面来定义自己

输出: 调性对照表（8 个维度）
  | 维度 | 新项目 | 对立面 |
检查:
  □ 每个维度都能说出"我不是什么"？
  □ 对照表能覆盖爽点/章末/情绪/章名/禁用词？
```

### 第 3 步 · 建锁定层（1-2 天）

```yaml
动作: 建三张卡
  A. 人设卡（主角 + 3-5 个主要角色）
     重点: 禁止项 5-8 个 + 漂移预警信号
  B. 金手指规则卡
     重点: 边界 > 能力；三条腿结构
  C. 世界观规则卡

检查:
  □ 主角的禁止项是否"可检查"？（不是"要克制"而是"不能怒吼"）
  □ 金手指是否有明确短板？
  □ 三条腿是否各有边界？
  □ 硬数据表是否建好？（年龄/姓名/关键数字）
```

### 第 4 步 · 建结构层（2-3 天）

```yaml
动作:
  A. 架构决策（关键，先定）:
     固定四卷（100-150万字）or 卷群制可生长（300万字+）
     判断: 有"更大的世界"可走 → 卷群制；讲完就真完了 → 固定四卷
  B. 卷群规划（若用卷群制）:
     卷群1 完整设计；卷群2-3 只做骨架；留 2-3 个生长点
  C. 逐章章纲（每章 100 字摘要 + 暗爽点 + 伏笔标记）
  D. 伏笔编号表（单级 F# / 两级 L#+C#）
  E. 爽点事件库（40+ 事件，四类轮换）

检查:
  □ 架构已定？（固定四卷 or 卷群制）
□ 若卷群制: 每个卷群是否"可独立告一段落"且留钩子？
□ 是否留了 2-3 个生长点？（可续可收）
□ 卷群是否有独立核心冲突 + 收束？
  □ 章纲是否每章都有暗爽点？
  □ 伏笔是否编号（含埋设章/回收章）？
  □ 事件库是否够 40+？（防中段枯竭）
```

### 第 5 步 · 建执行层（1 天）

```yaml
动作:
  A. LLM system prompt（含全部铁律）
  B. 章纲模板
  C. 字数节奏规则（分层区间，非死数）
  D. 听书格式规范（三轨分离/一人一段/数字可读化）
  E. 红黄牌词表（本项目专属）
  F. 影视化规范（按第 1 步定的改编形态）

检查:
  □ prompt 是否包含"禁止项"而非只有"要怎样"？
  □ 字数是否分层区间？（禁止每章固定字数）
  □ 词表是否项目专属？（冷感词 vs 炸裂词）
  □ 影视化规范是否匹配改编形态？
```

### 第 6 步 · 建质检层（0.5 天）

```yaml
动作:
  A. 每章过程评审 Prompt（AI味/一致性/漂移/格式）
  B. 发布闸门（合规 / 黄金三章 / 批次终审）
  C. 漂移回调方案表（6 种漂移类型）
  D. 百分制评分卡

检查:
  □ 评审是否分层？（过程 ≠ 闸门）
  □ 是否有"防对立项目味"的检测项？
  □ 漂移回调方案是否具体？（不是"改好点"而是"安排纯技术章"）
```

### 第 7 步 · 小批量试产 → 评审 → 量产

```yaml
动作:
  A. 试产前 10 章
  B. 用质检层全审一遍
  C. 根据问题回调规则（不是只改正文）
  D. 回调后重跑，确认稳定
  E. 量产

关键认知:
  试产阶段发现的问题，要【回调规则】而不是【只改正文】
  → 改规则 = 后面 390 章都受益
  → 只改正文 = 后面还会犯同样的错
```

## 总检查清单（开新书时逐条打勾）

```yaml
【定位层】
□ 平台已定，规则已确认
□ 受众已定，代入门槛已评估
□ 改编形态已定
□ 差异化一句话说得清

【锁定层】
□ 人设卡（含 5-8 条禁止项）
□ 漂移预警信号表
□ 金手指边界（三条腿各有短板）
□ 调性"不是什么"对照表
□ 硬数据校验表

【结构层】
□ 四卷架构 + 卷末钩子
□ 逐章章纲（含暗爽点/伏笔标记）
□ 伏笔编号表（独立编号）
□ 爽点事件库 40+

【执行层】
□ LLM system prompt
□ 章纲模板
□ 字数分层区间（非死数）
□ 听书格式规范
□ 项目专属红黄牌词表
□ 影视化规范

【质检层】
□ 每章过程评审 Prompt
□ 发布闸门（合规/三章/批次）
□ 漂移回调方案
□ 百分制评分卡

【试产】
□ 前 10 章已试产
□ 全审已跑
□ 问题已回调到规则层
□ 重跑确认稳定
```

## 时间估算

```yaml
第 1 本（从零建方法论）: 慢，需反复试错
第 2 本（复用框架）:    1-2 周建基础设施
第 3 本及以后:          3-5 天可建好（框架已成熟）

关键: 方法论的价值在于【第 3 本开始加速】
     前两本是投资，第三本开始收红利
```

---

## 批量生产的三个提醒

```yaml
提醒1 · 项目间必须隔离:
  独立编号 / 独立 prompt / 独立词表
  否则 LLM 会串味（写惯炸裂，冷感也带嚣张）

提醒2 · 交替创作反而有益:
  两个调性相反的项目交替写，
  能互相冲淡 AI 味（模型不容易陷入单一套路）

提醒3 · 规则要"活得":
  试产发现的问题 → 回调规则文件 → 全项目受益
  不要把规则写成死的文档，要当成"可迭代的代码"
```

---

## 一句话总结

> **7 步建好基础设施，前 10 章试产回调，然后量产。**
> 第 1 本慢，第 2 本快，第 3 本开始真正批量。
> **方法论的回报，从第 3 本书开始兑现。**
