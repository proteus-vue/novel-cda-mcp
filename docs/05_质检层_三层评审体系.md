# 质检层 · 三层评审体系

> **评审不是"打分"，是"分层拦截"。**
> 过程评审管质量，发布闸门管生死，漂移回保管纠偏。

---

## 一、为什么评审必须分层

```yaml
混淆的后果:
  只用过程评审 → 过松，发出事故（违规下架/崩人设掉粉）
  只用闸门评审 → 过严，无法量产（每章都改，产能归零）

✅ CDA 三层:
  第1层 · 每章过程评审（写完就审，管质量）
  第2层 · 批次/发布闸门（发布前审，管生死）
  第3层 · 漂移回调机制（发现问题，怎么救）
```

---

## 二、第一层：每章过程评审

```yaml
时机: 每章正文生成后
频率: 100%（每章必过）
重点: 质量（AI味 / 油腻味 / 调性漂移 / 格式）

四项检查:
  1. AI 味审计:
     - 红牌词 ≤1/章？
     - 有无总结升华式结尾？
     - 抽象情绪是否已替换为具体？
  2. 设定一致性:
     - 硬数据正确？（人名/数字/年龄）
     - 金手指边界是否被突破？
     - 人设禁止项是否被违反？
  3. 调性漂移:
     - 主角是否开始"解释/怒吼/炫耀"？
     - 是否混入了对立项目的味道？
  4. 格式合规:
     - 三轨分离？一人一段？数字可读化？
     - 引号闭合？无括号大段？

输出: 通过 / 打回重写（附具体问题）
```

## 三、第二层：发布闸门（一票否决制）

```yaml
时机: 每批次发布前 / 投稿前
频率: 每 30 章一批 + 首发前专项
重点: 生死（合规 / 黄金三章 / 伏笔健康）

闸门A · 合规终审（一票否决）:
  通用红线: 涉政 / 涉黄 / 暴力虐杀 / 违法教学
  项目专项:
    默者: 技术细节可复现？真实企业名？过度悲情？
    狂臣: 真实朝代？民族影射？暴力尺度？
  处理: 致命 → 禁止发布；严重 → 修改后发

闸门B · 黄金三章专项（生死线）:
  默者前三章:
    □ 300字内交代"被裁"
    □ 具体数字建立中年重量
    □ 金手指触发
    □ 家庭软肋落地
  狂臣前三章:
    □ 第1章压抑（无人迎）
    □ 第2章挑衅拉满 + 主角"笑了"
    □ 第3章当场掀桌 + 狠话
  判定: 读完不想看第4章 → 不达标，重写

闸门C · 批次/全书终审:
  □ 人设无漂移
  □ 爽点密度达标
  □ 伏笔健康（回收率/无凭空回收）
  □ 章名合规（≥5字/≤15字/分层）
  □ 字数分布不机械
  □ 存稿 ≥30 章
```

### 百分制评分卡

> **★ 先看这条（2026-09-15 实测修正）：没有扣分锚点的评分卡，分数不可复现。**
> 只给维度分值、不给"什么情况扣几分"，同一章由不同评分者评能差 5–8 分。
> 实测：同一批 15 章，"无锚点严评"得均 86.9（达标 2/15），
> "装锚点后"得均 91.5（达标 10/15）——**差的 4.6 分是测量误差，不是质量差**。
> 更严重的是跨项目不可比：A 项目按印象分给 90–96，B 项目按逐项找问题给 84–92。
> **做法：评分只报"命中哪一档"，不报"感觉多少分"；命中多档取最低档。**
> 锚点样板见各项目包《发布前最终评审方案》的「扣分锚点」节。

```yaml
合规:     一票否决（不计分）
人设/调性: 30 分
结构与爽点: 25 分
连续与伏笔: 20 分
文字与格式: 25 分

判定:
  ≥80 且无致命项 → 放行
  70-79         → 修改后发布
  <70 或有致命项 → 禁止发布
```

## 四、第三层：漂移回调机制

```yaml
核心问题: 发现漂移了，怎么救？

漂移类型与回调方案:

类型1 · 主角话变多了（默者）:
  症状: 王默开始长篇解释计划
  回调: 安排"纯技术操作章"（少对话，只写敲命令/看日志）

类型2 · 主角变隐忍（狂臣）:
  症状: 萧彻开始"等待时机"
  回调: 立刻安排"炸裂章"（金殿大场面，连放三次狠话+当场碾压）

类型3 · 爽点变廉价:
  症状: 反派一碰就倒，无抵抗
  回调: 给反派加"三条腿"（情报/权力/退路），让主角赢得艰难

类型4 · AI 味堆积:
  症状: 连续多章出现抽象情绪
  回调: 用"对照样本"重写该章，强制物件/动作/数字

类型5 · 油腻腔（爽文）:
  症状: 狂妄一笑/全场震惊反复出现
  回调: 删光形容词，只留动作与声音

类型6 · 注水:
  症状: 章节无暗爽点，为凑字数
  回调: 砍到"卡点"为止，宁可短章
```

## 五、评审的 Prompt 化（可直接复制）

```yaml
三个必建 Prompt:
  1. 每章 AI 味审计 Prompt（每章跑）
  2. 每章设定一致性 Prompt（每章跑）
  3. 周期全检 Prompt（每 10 章跑，对比第1章看调性漂移）

关键技巧:
  - 让 LLM 自己审自己（换个角色身份）
  - 输出必须是"问题清单 + 具体位置"，不能只说"还行"
  - 设定"一票否决项"，避免 LLM 和稀泥
```

## 六、发布前 Checklist（打印级）

```yaml
【合规】
□ 无真实企业名/朝代名/民族影射
□ 技术描写停留在流程层面
□ 无涉政/涉黄/暴力虐杀/违法教学
□ 无过度悲情、卖惨、绝望虚无

【三章】
□ 300字内进冲突（不铺垫世界观）
□ 核心钩子到位（被裁/归来）
□ 金手指触发
□ 读完想看第4章

【批次】
□ 人设无漂移
□ 爽点密度达标
□ 每章结尾是"卡点"
□ 伏笔无遗漏/无凭空回收
□ 数据连续
□ 章名分层且字数合规
□ 字数分布不机械

【运营】
□ 存稿 ≥30 章
□ 书名/简介/封面就绪
□ 日更计划可行
```

## 七、一句话总结

> **过程评审保质量，发布闸门保生死，回调机制保纠偏。**
> 三层各司其职，才能既"发得出去"又"量产得动"。
