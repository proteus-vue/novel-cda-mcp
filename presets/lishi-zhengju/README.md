# 大禹 · 历史正剧风格预设（lishi-zhengju）

第五个**可运行的风格 preset 样例**，与 [古言权谋](../guyan-quanmou/README.md)、[硬科幻](../hard-scifi/README.md)、[轻喜剧](../qing-xiju/README.md)、[悬疑推理](../xuanyi-tuili/README.md) 一起，验证大禹「多风格 = 整包配置切换，不改代码、不训练模型」的机制。

> 选历史正剧是因为它的两条专属红线（网络流行语、系统流面板）恰好是**其他所有包（含轻喜剧）的合法区**——轻喜剧甚至鼓励网络口语。这种「我禁的恰是你放的」反向差异，是证明每个 preset 独立判定体系的最强证据。

## 能力边界（诚实说明）

| 风格体征 | 归属 | 例子 |
|---|---|---|
| 可计算 | L1/L2 规则（本包 rules.yaml） | 网络流行语、系统流弹窗词、现代物件词、全场震惊式浮夸反应 |
| 半可计算 | 弱信号（suspect + 证据） | 时代错位、爽文化漂移、人物脸谱化、史料倾倒、天降解围 |
| 只能语义 | L3 prompt（本包 prompts.md，交调用方 AI） | 史观是否稳、厚重感是否立得住、人物动机是否有层次、时代语感是否统一 |

**规则扫不出"史观正不正、厚重够不够"** —— 和大禹一贯的边界一致：能规则化的做成 preset，史观与厚重感这种主观的东西必须交给 L3 语义评审与人类判断。L1 只能守住"别出戏、别弹窗"。

## 怎么用

`CDA_CONFIG_DIR` 在**进程启动时**读取（模块顶层加载），要在启动命令前设置：

```bash
pnpm build
export CDA_CONFIG_DIR=/绝对路径/novel-cda-mcp/presets/lishi-zhengju
node dist/index.js --doctor --json    # 应显示 大禹·历史正剧 / 0.2.0-zhengju.1 / healthy=true
node dist/index.js                     # stdio 模式，供写稿 Agent 挂载
```

`--doctor` 输出应见：

```
display_name: 大禹·历史正剧
rule_version: 0.2.0-zhengju.1
config_dir: .../presets/lishi-zhengju
```

不设 `CDA_CONFIG_DIR` 即用回默认网文包；指向别家 preset 互不影响。

### MCP 客户端配置示例

```json
{
  "mcpServers": {
    "novel-cda-zhengju": {
      "command": "node",
      "args": ["/绝对路径/novel-cda-mcp/dist/index.js"],
      "env": {
        "CDA_CONFIG_DIR": "/绝对路径/novel-cda-mcp/presets/lishi-zhengju",
        "CDA_MCP_DATA": "/长期保留/无中文无空格/目录"
      }
    }
  }
}
```

## 验证

`test/regression.test.ts` 的 `多风格 preset · 历史正剧` 测试块固化了断言（含**交叉反向验证**）：

1. preset 三件套齐全
2. 加载后 display_name/版本切换、规则一致性通过、4 个 prompt key 齐全
3. preset 的 doctor 健康（fail=0）
4. **网络流行语差异**：「家人们/破防了/yyds」文本在默认、古言、硬科幻、悬疑四包通过，轻喜剧包也通过，历史正剧包 `fatal=true`（`internet_slang_leak`）
5. **系统流差异**：「叮，恭喜宿主，系统绑定成功，属性面板已开启」文本在其他五包均通过，历史正剧包 `fatal=true`（`system_panel_leak`；测试刻意去掉感叹号，避免古言包因 `exclamation_in_title` 误伤而污染归因）
6. **双向交叉**：网络口语在轻喜剧包合法、历史正剧包 fatal（与轻喜剧 README 的断言正好互证）
7. 六风格互不污染：正剧包后切回轻喜剧包仍是轻喜剧规则

六包对同一批文本的判定矩阵：

| 文本 | 默认 | 古言 | 硬科幻 | 轻喜剧 | 悬疑 | 历史正剧 |
|---|---|---|---|---|---|---|
| 玄学词（真气/金丹） | 通过 | 通过 | fatal | 通过 | 通过 | 通过 |
| 精确数据（137.5米/0.3%） | 通过 | fatal | 通过 | 通过 | 通过 | 通过 |
| 现代词（手机/微信/186） | 通过 | fatal | 通过 | 通过 | 通过 | 通过 |
| 网络梗（家人们/破防/yyds） | 通过 | fatal | 通过 | 合法鼓励 | 通过 | **fatal** |
| 系统流（叮，恭喜宿主/属性面板） | 通过 | 通过 | 通过 | 通过 | 通过 | **fatal** |
| 苦情（吐血/生离死别） | 通过 | 通过 | 通过 | fatal | 通过 | 通过 |
| 破案跳步（轻而易举破解） | 通过 | 通过 | 通过 | 通过 | fatal | 通过 |

跑法：`pnpm test`（单元 + smoke 全绿）。

## 设计要点

1. **保留通用基准判据**：`reproducible_command`、`internal_marker_leak`、`pacing_signals` 通用基准词、`word_bands.通用` 全部保留——doctor 自检样本依赖它们。
2. **反向差异最能证明独立性**：正剧禁的网络梗/系统流恰是其他包（含轻喜剧）的合法区——这种「我禁你放」比单向差异更有说服力。
3. **软信号不判死**：时代错位/爽文化这类需要语境判断的放 classifier 与 anti_drift（suspect），只有铁定出戏的网络梗/系统弹窗才进 L1 fatal。
4. **权重/字数档随风格重排**：正剧把权重压在"人物厚度 30"、字数档往上调（史诗/权谋偏大）——配置本身就是风格宣言。

新增风格见 [主 README 的多风格章节](../../README.md#多风格预设preset) 与 [古言 preset README 的「如何新增」](../guyan-quanmou/README.md#如何新增一个风格-preset)。
