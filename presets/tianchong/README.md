# 大禹 · 甜宠言情风格预设（tianchong）

第六个**可运行的风格 preset 样例**，与 [古言权谋](../guyan-quanmou/README.md)、[硬科幻](../hard-scifi/README.md)、[轻喜剧](../qing-xiju/README.md)、[悬疑推理](../xuanyi-tuili/README.md)、[历史正剧](../lishi-zhengju/README.md) 一起，把大禹「多风格 = 整包配置切换，不改代码、不训练模型」的机制扩展到言情品类。

> 选甜宠是因为它的两条专属红线（强制爱、BE 结局）在另外五包都是合法区，而它和轻喜剧构成有趣的「一对反义词」：轻喜剧禁苦情、甜宠禁狗血虐心；轻喜剧靠反差制造笑点，甜宠靠细节制造心动——同属轻松向，判定体系却各自独立。

## 能力边界（诚实说明）

| 风格体征 | 归属 | 例子 |
|---|---|---|
| 可计算 | L1/L2 规则（本包 rules.yaml） | 强制爱词、BE 结局词、虐心套路词、油腻情话、吃醋/冷战信号 |
| 半可计算 | 弱信号（suspect + 证据） | 虐心化、工具人化、情话油腻、狗血三角、甜度扁平 |
| 只能语义 | L3 prompt（本包 prompts.md，交调用方 AI） | 心动是否成立、甜度是否自然、是否双向自愿、HE 是否圆满 |

**规则扫不出"这个心动真不真"** —— 和大禹一贯的边界一致：能规则化的做成 preset，心动与甜度这种主观的东西必须交给 L3 语义评审与人类判断。L1 只能守住"别强制、别 BE"。

## 怎么用

`CDA_CONFIG_DIR` 在**进程启动时**读取（模块顶层加载），要在启动命令前设置：

```bash
pnpm build
export CDA_CONFIG_DIR=/绝对路径/novel-cda-mcp/presets/tianchong
node dist/index.js --doctor --json    # 应显示 大禹·甜宠言情 / 0.2.0-tianchong.1 / healthy=true
node dist/index.js                     # stdio 模式，供写稿 Agent 挂载
```

`--doctor` 输出应见：

```
display_name: 大禹·甜宠言情
rule_version: 0.2.0-tianchong.1
config_dir: .../presets/tianchong
```

不设 `CDA_CONFIG_DIR` 即用回默认网文包；指向别家 preset 互不影响。

### MCP 客户端配置示例

```json
{
  "mcpServers": {
    "novel-cda-tianchong": {
      "command": "node",
      "args": ["/绝对路径/novel-cda-mcp/dist/index.js"],
      "env": {
        "CDA_CONFIG_DIR": "/绝对路径/novel-cda-mcp/presets/tianchong",
        "CDA_MCP_DATA": "/长期保留/无中文无空格/目录"
      }
    }
  }
}
```

## 验证

`test/regression.test.ts` 的 `多风格 preset · 甜宠言情` 测试块固化了断言（含**交叉反向验证**）：

1. preset 三件套齐全
2. 加载后 display_name/版本切换、规则一致性通过、4 个 prompt key 齐全
3. preset 的 doctor 健康（fail=0）
4. **强制爱差异**：「下药/强行占有/强迫发生关系」文本在其他六包均通过，甜宠包 `fatal=true`（`forced_love_leak`）
5. **BE 结局差异**：「孤独终老/相忘于江湖/从此没再见面」文本仅甜宠包 fatal（`bad_ending_leak`）
6. **与轻喜剧的分野**：苦情文本（吐血/生离死别）在轻喜剧包 fatal、甜宠包因 `melodrama_drift` 是 L2 serious 而非 L1 fatal——两个轻松向风格判定体系不同
7. 七风格互不污染：甜宠包后切回古言包仍是古言规则

七包对同一批文本的判定矩阵：

| 文本 | 默认 | 古言 | 硬科幻 | 轻喜剧 | 悬疑 | 正剧 | 甜宠 |
|---|---|---|---|---|---|---|---|
| 玄学词（真气/金丹） | 通过 | 通过 | fatal | 通过 | 通过 | 通过 | 通过 |
| 精确数据（137.5米/0.3%） | 通过 | fatal | 通过 | 通过 | 通过 | 通过 | 通过 |
| 现代词（手机/微信/186） | 通过 | fatal | 通过 | 通过 | 通过 | 通过 | 通过 |
| 网络梗（家人们/破防） | 通过 | fatal | 通过 | 合法鼓励 | 通过 | fatal | 通过 |
| 系统流（叮！恭喜宿主） | 通过 | 通过 | 通过 | 通过 | 通过 | fatal | 通过 |
| 苦情（吐血/生离死别） | 通过 | 通过 | 通过 | fatal | 通过 | 通过 | 通过 |
| 破案跳步（轻而易举破解） | 通过 | 通过 | 通过 | 通过 | fatal | 通过 | 通过 |
| 强制爱（下药/强迫） | 通过 | 通过 | 通过 | 通过 | 通过 | 通过 | **fatal** |

## 设计要点

1. **保留通用基准判据**：`reproducible_command`、`internal_marker_leak`、`pacing_signals` 通用基准词、`word_bands.通用` 全部保留——doctor 自检样本依赖它们。
2. **L1 只判铁定的契约破坏**：强制爱/BE 是甜宠契约的硬底线，进 L1 fatal；虐心狗血是需要语境判断的，放 L2/anti_drift（suspect）。
3. **同类风格也要独立判定**：甜宠与轻喜剧同属轻松向，但一个禁苦情、一个禁狗血，禁的东西不同、禁的层级也不同——证明 preset 不是按大类粗分。
4. **权重/字数档随风格重排**：甜宠把权重压在"情感甜度 30"、字数档往下调（甜暖/撒糖偏小）——配置本身就是风格宣言。

新增风格见 [主 README 的多风格章节](../../README.md#多风格预设preset) 与 [古言 preset README 的「如何新增」](../guyan-quanmou/README.md#如何新增一个风格-preset)。
