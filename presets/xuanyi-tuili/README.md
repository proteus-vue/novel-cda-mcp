# 大禹 · 悬疑推理风格预设（xuanyi-tuili）

第四个**可运行的风格 preset 样例**，与 [古言权谋](../guyan-quanmou/README.md)、[硬科幻](../hard-scifi/README.md)、[轻喜剧](../qing-xiju/README.md) 一起，把大禹「多风格 = 整包配置切换，不改代码、不训练模型」的机制扩展到推理品类。

> 选悬疑推理是因为它的两条专属红线（破案跳步、超自然谜底）在另外三包都是合法区，而它放开的精确数据与网络口语又分别撞上古言包的数字红线和古言包的现代词红线——交叉差异最能证明每个 preset 是独立判定体系。

## 它改了什么（对比）

| 现代口语/网络词 | 合法 | 禁（fatal） | 合法 | 合法且鼓励 | 合法 |
| 精确数字 | 合法 | 禁（fatal） | 合法且鼓励 | 合法 | 合法 |

## 能力边界（诚实说明）

| 风格体征 | 归属 | 例子 |
|---|---|---|
| 可计算 | L1/L2 规则（本包 rules.yaml） | 破案跳步词、超自然谜底词、线索藏私句式、反派自白、凶器/作案细节软信号 |
| 半可计算 | 弱信号（suspect + 证据） | 反转无铺垫、红鲱鱼滥用、侦探全知、逻辑断链 |
| 只能语义 | L3 prompt（本包 prompts.md，交调用方 AI） | 诡计是否精妙、线索是否真正公平、读者能否推出真相、反派博弈是否有张力 |

**规则扫不出"这个诡计精不精妙"** —— 和大禹一贯的边界一致：能规则化的做成 preset，谜题巧思这种主观的东西必须交给 L3 语义评审与人类判断。L1 只能守住"别跳步、别拿鬼神糊弄"。

## 怎么用

`CDA_CONFIG_DIR` 在**进程启动时**读取（模块顶层加载），要在启动命令前设置：

```bash
pnpm build
export CDA_CONFIG_DIR=/绝对路径/novel-cda-mcp/presets/xuanyi-tuili
node dist/index.js --doctor --json    # 应显示 大禹·悬疑推理 / 0.2.0-tuili.1 / healthy=true
node dist/index.js                     # stdio 模式，供写稿 Agent 挂载
```

`--doctor` 输出应见：

```
display_name: 大禹·悬疑推理
rule_version: 0.2.0-tuili.1
config_dir: .../presets/xuanyi-tuili
```

不设 `CDA_CONFIG_DIR` 即用回默认网文包；指向别家 preset 互不影响。

### MCP 客户端配置示例

```json
{
  "mcpServers": {
    "novel-cda-tuili": {
      "command": "node",
      "args": ["/绝对路径/novel-cda-mcp/dist/index.js"],
      "env": {
        "CDA_CONFIG_DIR": "/绝对路径/novel-cda-mcp/presets/xuanyi-tuili",
        "CDA_MCP_DATA": "/长期保留/无中文无空格/目录"
      }
    }
  }
}
```

## 验证

`test/regression.test.ts` 的 `多风格 preset · 悬疑推理` 测试块固化了断言（含**交叉反向验证**）：

1. preset 三件套齐全
2. 加载后 display_name/版本切换、规则一致性通过、4 个 prompt key 齐全
3. preset 的 doctor 健康（fail=0）
4. **破案跳步差异**：「轻而易举破解/很快抓住凶手」文本在默认/古言/硬科幻/轻喜剧四包通过，悬疑包 `fatal=true`（`skipped_deduction_leak`）
5. **超自然谜底差异**：「原来是鬼/凶手是鬼」文本仅悬疑包 fatal（`supernatural_solution_leak`），硬科幻包靠 `xianxia_leak` 也能拦但命中 id 不同
6. **交叉反向**：精确数字在古言包 fatal、悬疑包合法；苦情文本在轻喜剧包 fatal、悬疑包合法
7. 五风格互不污染：悬疑包后切回硬科幻包仍是硬科幻规则

五包对同一批文本的判定矩阵：

| 文本 | 默认 | 古言 | 硬科幻 | 轻喜剧 | 悬疑推理 |
|---|---|---|---|---|---|
| 玄学词（真气/金丹/筑基） | 通过 | 通过 | fatal | 通过 | 通过 |
| 精确数据（137.5米/0.3%） | 通过 | fatal | 通过 | 通过 | 通过 |
| 现代词（手机/微信/186） | 通过 | fatal | 通过 | 通过 | 通过 |
| 苦情（吐血/生离死别） | 通过 | 通过 | 通过 | fatal | 通过 |
| 破案跳步（轻而易举破解） | 通过 | 通过 | 通过 | 通过 | **fatal** |
| 超自然谜底（原来是鬼） | 通过 | 通过 | 通过 | 通过 | **fatal** |

跑法：`pnpm test`（单元 + smoke 全绿）。

## 设计要点

1. **保留通用基准判据**：`reproducible_command`、`internal_marker_leak`、`pacing_signals` 通用基准词、`word_bands.通用` 全部保留——doctor 自检样本依赖它们。
2. **风格红线放 L1，风格信号放 L2**：破案跳步/超自然谜底必须进 `hard_reject`（fatal），红鲱鱼滥用/逻辑断链这类放 classifier 或 anti_drift（suspect）。
3. **交叉差异比单向差异更有说服力**：悬疑放开的精确数字恰是古言红线、悬疑禁的苦情恰是轻喜剧红线——交叉证明每个 preset 是独立判定体系。
4. **权重/字数档随风格重排**：悬疑把权重压在"逻辑闭环 30"、字数档往上调（缜密/惊险偏中上）——配置本身就是风格宣言。

新增风格见 [主 README 的多风格章节](../../README.md#多风格预设preset) 与 [古言 preset README 的「如何新增」](../guyan-quanmou/README.md#如何新增一个风格-preset)。
